# 点球读人辅助器

一个单文件网页，双击 `index.html` 就能用（手机浏览器也行）。
你每罚一球记一笔，它告诉你**下一球踢哪边**、以及你守门时**该扑哪边**。

> 先说清楚它是什么：它不是外挂，改不了游戏。它做的只有一件事——**把你和对手已经暴露出来的习惯，变成下一次的概率**。对手越有规律，它越准；对手真随机，它最多帮你做到「不被他读」。

---

## 零、手机上怎么用

**方案 A：电脑开着，手机走局域网（推荐，30 秒搞定）**

1. 双击 `启动.bat`（黑窗口别关，关了服务就停）。
2. 手机连**同一个 Wi-Fi**，浏览器地址栏输入窗口里打印的地址，形如 `http://192.168.31.235:8765`。
3. 加到主屏幕当 App 用：
   - iPhone：Safari 打开 → 分享按钮 → **添加到主屏幕**
   - 安卓：Chrome 打开 → 右上角 ⋮ → **添加到主屏幕**
4. 之后点图标直接全屏打开，没有地址栏。

手机打不开的话，九成是 Windows 防火墙拦了 Python：控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 找到 `python.exe`，把**专用/公用**两个都勾上。或者把当前 Wi-Fi 的网络类型改成「专用网络」。

**方案 B：安卓离线，不依赖电脑**

1. 把 `index.html` 通过 QQ「我的电脑 / 文件传输助手」发到手机并下载。
2. 用文件管理器找到它 → 打开方式选 Chrome；或在 Chrome 地址栏输 `file:///sdcard/Download/index.html`。
3. 记录存在本地，能一直用；换设备就靠下面的「导出备份」。

**方案 C：iPhone 想彻底脱离电脑**

Safari 不支持直接打开本地 html（点了只看得到源码）。要么用方案 A，要么把这个文件丢到任意静态托管（GitHub Pages、对象存储、你自己的服务器），拿一个 `https://` 链接再「添加到主屏幕」。走这条路还能顺便在电脑和手机之间同步。

> **别在 QQ / 微信里直接点开 html**：那只是文件预览，脚本经常不跑，就算跑了记录也存不住（域名/路径是临时的）。

### 过一天就打不开了？

不是网页坏了，是**那个地址背后的小服务没了**。`http://192.168.31.235:8765` 能打开，靠的是电脑上跑着一个 Python 小服务；电脑关机、或者那个进程被结束，地址自然就打不开。第二种可能是路由器重新分配了 IP，旧地址换了人。

现在这两件事都处理了：

- **开机自启**：`启动文件夹` 里放了 `点球辅助器.vbs`，登录 Windows 后自动在后台把服务拉起来（无窗口，不弹任何东西）。删掉这个 vbs 就取消自启。
- **IP 会变**：客户端用 `http://LU:8765`（`LU` 是这台电脑的名字），或者双击 `启动.bat` 看当前 IP。

| 想干什么 | 双击 |
|---|---|
| 现在就要用 / 检查服务在不在 | `启动.bat`（会在后台拉起并打印当前地址） |
| 不想让它跑了 | `停止服务.bat` |
| 不再开机自启 | 删掉启动文件夹里的 `点球辅助器.vbs` |

顺带记一下：手机上的**记录不会因为服务停了而丢**（存在浏览器 localStorage 里），重新连上同一个地址还在。但如果 IP 变了，地址变了，数据就相当于换了个「网站」，得先导出备份再导入。

### 装到桌面（PWA，有图标、全屏）

现在这个版本已经带上 PWA 三件套：`manifest.webmanifest`、`sw.js`、`icons/`。所以**在局域网地址上就能装**：

- iPhone：Safari 打开 → 分享 → 添加到主屏幕
- 安卓：Chrome → ⋮ → 添加到主屏幕 / 安装应用

装完是独立图标、全屏、没有地址栏。**但它仍然要连电脑**——因为 `http://` 不属于「安全上下文」，Service Worker 注册不了，没有离线缓存。

### 想真正断网、关机也能开（离线能力）

需要一次 `https://` 的打开。这一步我替你做不了，原因说清楚：

- 免费隧道（localhost.run、pinggy）在你这边的网络上，域名被 DNS 污染 / 连不上；
- 从 GitHub 下 cloudflared 的 40MB 安装包，被限速卡在 1.5MB 不动；
- 所以「凭空给你一个公网 https 地址」这条路在本地走不通。

**你自己有地方托管静态页就行**（GitHub Pages、自己的服务器、对象存储都行），要点：

1. **整个文件夹原样上传**，别只传 `index.html`——`sw.js`、`manifest.webmanifest`、`icons/` 必须同目录。
2. 手机打开一次那个 `https://` 地址，等 2 秒（缓存写入），再「添加到主屏幕」。
3. 之后断网、关电脑都能打开；数据照旧存在手机本地。
4. 改了代码要重新部署，手机端**刷新两次**才会换到新缓存。
5. 换了地址等于换了「站点」，老记录不会跟过去，先「导出备份」。

**安卓还有个保底方案**：把 `index.html` 传到手机，用 Chrome 打开（`file://`），加到桌面也能用，完全离线、不依赖任何服务。iOS 不行（Safari 不给本地 html 跑脚本）。

**跨设备搬数据**：页面最下面「数据 & 自检」里有 **导出备份 / 导入备份**。换手机、换 IP、换地址之前先导出，粘到备忘录里，到新环境粘回去即可。

## 一、怎么用

1. 双击 `index.html`（推荐用 Edge / Chrome）。
2. 手机上：把文件传过去，用浏览器打开，菜单里「添加到主屏幕」，用起来跟 App 一样。
3. 每罚完一球，在「记一球」里点四下：我踢哪边 / 结果 / 对方踢哪边 / 对方结果。**「对方门将扑向」能看清就选**，这个信息比进球结果值钱得多。
4. 顶部两张卡片就是答案：攻（我踢哪边）、守（我扑哪边）。
5. 记录只存在你本机浏览器里，刷新不丢，也不上传。

**方向约定：全按画面。** 你俩看的是同一块屏幕，画面左边就是「左」——不区分谁站哪边，也不用换视角，记录时按你看到的方向填就行。

## 二、它是怎么算的

### 进攻：`下一球踢哪边`

不是「对手爱扑哪边，我就避开哪边」这么简单，因为对手也会读你。所以模型算的是**你这一脚会被覆盖的概率**：

```
被覆盖概率(side) = 0.55 × 门将的扑救习惯(side)      ← 他本能会往哪倒
                 + 0.45 × 他对你的预判(side)        ← 他根据你的历史猜你踢哪
```

`他对你的预判`用的模型和 `他的习惯`是同一个——同一套函数喂你的历史射门序列，就等于在算「他会怎么猜你」。这叫**反读**（二阶推理）：你俩互相建模，谁的模式更明显谁就吃亏。这是行为预测，跟左右视角无关——你们看的是同一块画面。

然后：

```
期望进球(side) = 你的该侧命中率(side) × (1 − 0.5 × 被覆盖概率(side)) − 中路惩罚
```

取最大的那个。三项分别对应三种现实：

| 项 | 现实含义 |
|---|---|
| 该侧命中率 | 你左脚就是踢不好左边，模型不会硬推荐 |
| 1 − 被覆盖 | 门将扑对边也只有一定概率扑出，不是必死 |
| 中路惩罚 | 中路是赌：他扑出去必进，他站着不动就没了 |

### 防守：`我该扑哪边`

直接对**对方的射门序列**跑同一套预测，取概率最大的一侧。对方越爱固定一边、越爱「左左右右」地规律换边，这里越准。

### 序列预测内部（两项共用）

```
P(下一侧) = 0.50 × 近期加权频率   ← 近 3 球权重最高，越早越淡（半衰期约 3 球）
          + 0.30 × 一阶转移       ← 「他上一次是左，这次会去哪」的经验条件概率
          + 0.20 × 先验           ← 数据不够时兜底
```

再叠一层**压力修正**：从第 3 球起，惯用侧权重上调、中路下调。因为人在压力下会退回到最熟的动作，这是运动心理学里很稳的一条（choking under pressure / 自我聚焦导致动作回归自动化模式）。

## 三、用到的心理学，逐条对应

| 机制 | 人话 | 代码里在哪 |
|---|---|---|
| **赌徒谬误 / 负近因** | 连开三次「左」，人会觉得「该换了吧」——对手门将也这么想 | 一阶转移矩阵的先验就编码成「偏向换边」，连续同侧时预测掉头 |
| **热手错觉** | 反过来，也有人「上次扑对了就再来一次」 | 转移矩阵从**对手真实数据**里学，不写死；他的连扑率会被学出来 |
| **习惯化 + 优势侧偏好** | 紧张时人回到最熟的那边 | 压力修正项；以及你 60% 都在左侧时的「你太可预测」警告 |
| **交替启发式** | 人类自造随机时严重高估交替，实际是「ABABAB」不是随机 | 转移先验本身；也是「随缘模式」存在的理由 |
| **行动偏差（action bias）** | 门将宁可扑出去也不愿站着不动——哪怕站着不动更有效 | 中路先验只给 24%；Bar-Eli 等人 2007 年对顶级门将的统计里，站中间的比例只有个位数 |
| **承诺升级 / 沉没成本** | 上一球用某侧成功了，人会不自觉地继续用 | 近期频率权重（近 3 球权重最高）会捕捉这种黏性 |
| **后悔厌恶** | 刚被扑的那一侧，下一球会本能回避 | 你的「该侧命中率」会打折，模型跟着回避 |
| **二阶推理（反读）** | 对手也在读你，所以「避开他爱扑的边」不够 | `cover` 里 45% 的权重给了「他对你的预判」 |

一句话总结：**这工具不是在猜门将，是在猜「门将怎么猜你」。**

## 四、准确率：能到多少，以及为什么不能更高

诚实的部分：

1. **第一球没有任何信息**，只能靠先验（左右各 40%，中 20%）——这球靠自己。
2. **4 球以内的「规律」基本都是巧合**。界面在样本 < 4 时会把这句话直接糊你脸上。
3. **对手真随机时，上限就是 33%**。任何号称 90% 的点球预测都是骗人的：门将三选一，你最多把「被猜中」的概率从 33% 压到 20% 左右。
4. 所以真实收益不是「每球都猜中」，而是两件事：
   - 把对手的**可预测性**变成你的进球率（他爱扑右边 → 你多打左边）；
   - 提醒你**自己别被读**（你连着三球左边，界面会直接说「这不是秘密，门将也有眼睛」）。
5. 界面的「留一法自检」是拿你自己录的数据回头考模型：攻是「推荐方向有没有被扑到」，守是「猜没猜中对方射门方向」，旁边标了瞎猜基线（67% / 33%）。**样本 < 6 球时它不显示**，因为那个数字纯属噪声。

想要它准，最实在的做法：**同一个人、同一晚、连续记 8 球以上**。跨人混记等于没记。

## 五、几个使用建议

- **读人模式**适合对手有明显习惯（老往一边扑、爱规律换边）。
- **随缘模式**适合两种情况：样本太少；或者你已经把对手读明白了，但他也在读你——这时候纯随机（左 45% / 右 45% / 中 10%）比任何「聪明选择」都更难被针对。博弈论上，这本来就是点球博弈的均衡解。
- 比分落后、必须进的那一球：**别选中路**（界面会提示）。中路是赌，稳的时候要用你命中率最高的那边。
- 别在真人对抗里念出来。辅助器最大的价值是让你形成习惯，不是让你当众看手机。

## 五、博弈手段：从「读人」到「不可读」

「读人」有个天花板：你越会读他，他早晚也会读你。真正稳的是**混合策略**——让对手怎么猜都占不到便宜。所以这一版加了一个「博弈面板」：

### 1. 支付矩阵 + 纳什均衡

把点球当成一个 3×3 零和博弈：你选左/中/右，门将选扑左/中/右，矩阵里的值就是「进球概率」。

```
              门将扑左   门将扑中   门将扑右
我踢左          0.38      0.93      0.94
我踢中          0.93      0.36      0.93
我踢右          0.94      0.93      0.38
```

（先验来自真实点球统计：扑对边也常被穿，约四成能进；扑反边基本必进；中路被站住就很难进。你自己录的每一球会按伪计数逐步覆盖先验。）

然后用**虚构对局（fictitious play）**迭代求这个零和博弈的近似纳什均衡，得到一组配比，比如 `左 35% / 中 34% / 右 31%`，以及**均衡下期望进球率**——这个值的意思很硬：**不管门将怎么扑，你按这个配比随机出脚，期望进球率都不会低于它**。

面板还会算一个数：**你固定踢某一边时的最差情况**（他死守那边）。比如「固定踢中，最差 36%」，和均衡的 74% 差 38 个点——这个差距就是「被读懂」的代价。

### 2. 用加密随机数出脚

「均衡」模式不再是拍脑袋的 45/10/45，而是按上面算出的配比，用 `crypto.getRandomValues` 抽样。**人是极差的随机数发生器**：会过度交替、会避开连号、会在「该换了」的地方露出规律。交给加密随机数，比自己数着来更不会被抓。

### 3. 行为牌面（对手的三个可利用习惯）

| 牌面 | 怎么算 | 怎么用 |
|---|---|---|
| **连扑回避** | 他连续两次扑同一边的比例（随机基准 33%） | 明显低于 33% 时（赌徒谬误），他刚扑过的那边反而空着 → 踢那边 |
| **跟着你上一球** | 他扑的方向 = 你上一球方向的比例（基准 33%） | 明显高于 33% 时，反向踢 |
| **落后时偏哪侧** | 你领先时的扑救方向分布 | 研究显示落后时门将更常扑画面左侧（约七成）→ 打右边 |

这三条都带样本数（`2/4` 这种），样本不足时只会显示「牌面还不够」，不硬编故事。

### 4. 研究依据

- **混合策略均衡**：Chiappori, Levitt & Groseclose (2002), *Testing Mixed-Strategy Equilibria When Players Are Heterogeneous: The Case of Penalty Kicks in Soccer*, American Economic Review——职业球员的点球选择确实接近混合策略均衡，且中路被系统性低估。
- **中路被低估**：Bar-Eli et al. (2007), *Action bias among elite soccer goalkeepers*, Journal of Economic Psychology——门将 94% 会扑向一侧，只有约 6% 站中间；而中路射门成功率反而更高（[NYT 报道](http://www.nytimes.com/2008/12/14/magazine/14Ideas-Section2-B-t-008.html)）。
- **赌徒谬误**：Wood et al. (2014), *Asymmetric predictability and cognitive competition in football penalty shootouts*, Current Biology——门将会因为「刚才扑过这边」而倾向换边，但**射手并不会利用**（[UCL 新闻稿](https://archive.eurekalert.org/pub_releases/2014-07/ucl-gpt072814.php)）。这条是这个工具最实在的边际收益。
- **落后时偏右侧**：Roskes et al.（阿姆斯特丹大学）——球队落后时门将扑向自己右手边 71%，领先时只有 48%（换算到你们的共享画面即「左侧」）（[Irish Times 综述](https://www.irishtimes.com/opinion/2026/07/13/ian-robertson-a-neuropsychologists-advice-on-how-to-win-a-world-cup-penalty-shoot-out/)）。机制是「趋近动机」激活左前额，动作偏向身体右侧。
- **中路宽度**：*Goal center width, how to count sequences, and the gambler's fallacy in soccer penalty shootouts*, Judgment and Decision Making——用序列计数方式的不同会改变结论，提醒别过度解读「连开三次」。

## 六、局限

- 对**电脑 AI 门将基本无效**：AI 不吃心理学，它读的是输入时机和随机种子。
- 它不懂你踢球的力量、角度、假动作——只懂「边」。
- 别拿它去赌真钱。对真人点球大战，它只是个概率笔记本。
